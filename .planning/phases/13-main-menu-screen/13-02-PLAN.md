# Plan 13-02: Page Transitions

## Goal
Add smooth bidirectional animated transitions between the menu (`/`) and game (`/game`) using the SvelteKit `onNavigate` hook and the browser-native View Transitions API.

## Context
With routes split in Plan 13-01, every navigation between `/` and `/game` fires SvelteKit's `onNavigate` lifecycle hook in `+layout.svelte`. This plan wires that hook to `document.startViewTransition`, then adds the CSS `@keyframes` that animate the swap. The approach is consistent with the existing codebase style (CSS-only animations, no `svelte/transition` usage), handles both forward and back navigation, and degrades gracefully to an instant switch on unsupported browsers. This satisfies MENU-05 fully.

## Tasks

### Task 1: Add `onNavigate` hook to `+layout.svelte`
**File:** `src/routes/+layout.svelte`
**Action:** modify
**Details:**
Add the `onNavigate` import and call to the existing `<script lang="ts">` block. Do not remove or reorder any existing code.

The existing file is:
```svelte
<script lang="ts">
	import '../app.css';
	import OfflineIndicator from '$lib/components/OfflineIndicator.svelte';
	import { onMount } from 'svelte';
	import { initAdMob } from '$lib/effects/admob.js';

	const { children } = $props();

	onMount(() => {
		if (screen.orientation?.lock) {
			screen.orientation.lock('landscape').catch(() => {});
		}
		initAdMob();
	});
</script>
```

Add `onNavigate` import alongside `onMount` and add the hook call after the `onMount` block:

```svelte
<script lang="ts">
	import '../app.css';
	import OfflineIndicator from '$lib/components/OfflineIndicator.svelte';
	import { onMount } from 'svelte';
	import { onNavigate } from '$app/navigation';
	import { initAdMob } from '$lib/effects/admob.js';

	const { children } = $props();

	onMount(() => {
		if (screen.orientation?.lock) {
			screen.orientation.lock('landscape').catch(() => {
				// Browser may reject the lock outside a user gesture or on desktop — silently ignore
			});
		}
		initAdMob(); // non-blocking; no-op on web
	});

	onNavigate((navigation) => {
		if (!document.startViewTransition) return; // graceful degradation: instant switch
		return new Promise((resolve) => {
			document.startViewTransition(async () => {
				resolve();
				await navigation.complete;
			});
		});
	});
</script>

{@render children()}
<OfflineIndicator />
```

**Key detail:** `onNavigate` must return either nothing (for instant navigation) or a Promise. Returning the Promise delays SvelteKit's DOM swap until `resolve()` is called; `await navigation.complete` waits for the new page's DOM to be fully painted before ending the transition. This is the canonical SvelteKit 2 pattern.

### Task 2: Add View Transition CSS to `app.css`
**File:** `src/app.css`
**Action:** modify
**Details:**
Append the following CSS to the end of `src/app.css`. Do not modify any existing rules.

```css
/* ─── Page Transitions (View Transitions API) ─────────────────────────────── */

@keyframes fade-slide-in {
  from {
    opacity: 0;
    transform: translateY(16px);
  }
}

@keyframes fade-slide-out {
  to {
    opacity: 0;
    transform: translateY(-16px);
  }
}

::view-transition-old(root) {
  animation: 250ms ease-in fade-slide-out;
}

::view-transition-new(root) {
  animation: 250ms ease-out fade-slide-in;
}
```

**Effect:** When navigating to `/game`, the old page (menu) slides up and fades out while the new page (game) slides up from below and fades in. When pressing back, the directions reverse automatically because the View Transitions API swaps which element is "old" vs "new". The 250ms duration is fast enough to feel snappy on mobile without being jarring.

**Why `translateY` and not `translateX`:** The game is a vertical experience (mixing chamber stacked above discoveries). A vertical slide reads as "going deeper" into the app rather than a lateral page flip, which suits the alchemical theme.
