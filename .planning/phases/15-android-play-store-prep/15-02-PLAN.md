<task type="checkpoint:human-action" gate="blocking">
  <name>Task 1: Generate Play Store screenshots</name>
  <what-to-do>
Google Play requires a minimum of 2 phone screenshots. Capture them from a running
Android device or emulator.

Requirements:
  - Minimum: 2 phone screenshots
  - Accepted sizes: 1080×1920 (16:9) or 1080×2400 (20:9 / full-screen)
  - Format: PNG or JPEG, max 8 MB each
  - Optional (recommended): 7-inch tablet and 10-inch tablet screenshots

Option A — Android device/emulator (recommended):
  1. Build and install the app on a device or emulator:
     ```
     npm run build
     npx cap sync android
     ```
     Then in Android Studio: Run → Run 'app' on your chosen device/emulator.
  2. Play through the game to reach interesting states (mixing screen, discovery, etc.).
  3. Take screenshots using the device power+volume-down buttons OR Android Studio's
     screenshot button (camera icon in the Running Devices panel).
  4. Transfer screenshots to your computer. Suggested filenames:
     - `screenshot-01-mixing.png`
     - `screenshot-02-discovery.png`
     (Add more for better store presentation.)

Option B — Browser emulation (quick):
  1. Open `npm run dev` → navigate to the game page.
  2. Open Chrome DevTools → Toggle device toolbar → set to 1080×1920.
  3. Use DevTools screenshot (⋮ menu → "Capture screenshot").
  Note: browser screenshots won't show native UI chrome — acceptable for Play Store.

Store these screenshots in `assets/screenshots/` (create folder if needed).
  </what-to-do>
  <resume-signal>Type "screenshots-done" when you have at least 2 phone screenshots ready (1080×1920 or 1080×2400).</resume-signal>
</task>

<task type="checkpoint:human-action" gate="blocking">

Fill in all required metadata fields in Google Play Console. Red exclamation marks (!)
indicate required fields — all must be resolved before submission.

Steps:
  1. Open https://play.google.com/console → select app **Alchemica** (io.alchemica.app).
  2. Left menu: **Grow** → **Store presence** → **Main store listing**.

  --- App details section ---
  3. App name: `Alchemica`  (max 50 chars)
  4. Short description (max 80 chars — appears in search results):
     `Combine elements to discover 32 alchemical compounds. How many can you find?`
     (Adjust to ≤80 chars if needed.)
  5. Full description (max 4000 chars — shown on store page):
     ```
     Alchemica is a relaxing element-combination puzzle game.

     Start with the four classical elements — Fire, Water, Earth, and Air — then combine
     them to discover 32 unique alchemical compounds. Mix metals, gases, and mysterious
     energies as you uncover the secrets of alchemy one reaction at a time.

     Features:
     • 32 discoverable elements across 9 categories
     • Satisfying combination mechanics — drag, drop, and react
     • Discovery log tracking every combination you've found
     • Daily challenge for a new puzzle every day
     • Achievements and combo scoring
     • Hint system for when you're stuck
     • Fully offline — no internet required
     • No account needed — progress saves automatically

     How many elements can you discover?
     ```
     (Edit freely — this is a suggested template.)

  --- Graphics section ---
  6. App icon: Upload your 512×512 PNG icon.
     If you don't have one, use the icon from `assets/` or export one from Android Studio:
     Android Studio → res/mipmap-xxxhdpi/ic_launcher.png (108×108 dp = 432px at 4x density).
     For Play Store you need exactly 512×512.
  7. Feature graphic (1024×500 PNG/JPEG) — required:
     Create a simple banner: dark background (#0d1b2e) with "Alchemica" text and a few element icons.
     Tools: Canva, Figma, or any image editor. Export as 1024×500 PNG.

     Drag them into the "Phone" section.

  --- Click "Save" ---
  9. Scroll to the top and click **Save** (or **Save draft**).
  10. Confirm: no red (!) icons remain on the Main store listing page.
  </what-to-do>

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 3: Complete content rating questionnaire and set app category</name>
  <what-to-do>
Google Play requires a content rating for all apps. The questionnaire takes ~5 minutes.

--- Content rating ---
  1. Left menu: **Policy** → **App content** → find "Content ratings" section → click "Start questionnaire".
     (Alternatively: left menu → **Ratings** if it appears directly.)
  2. Select category: **Games**.
  3. Answer questions honestly:
     - Violence: No (the game has no violence — element combination only)
     - Sexual content: No
     - Profanity: No
     - Controlled substances: No
     - User interaction / social features: No (unless you added multiplayer — you haven't)
     - Gambling: No (hint purchases are cosmetic, not gambling mechanics)
  4. Click **Save questionnaire** → then **Calculate rating**.
  5. The expected rating is **IARC: Everyone / PEGI 3 / ESRB E** — confirm and click **Apply rating**.
  6. The Ratings page should now show a green check.

--- App category ---
  7. Left menu: **Grow** → **Store presence** → **Store settings**.
  8. Under "App category":
     - App or game: **Game**
     - Category: **Puzzle**
  9. Tags (optional but recommended): add `Casual`, `Brain & Puzzle`, `Alchemy`.
  10. Click **Save**.
  </what-to-do>
  <resume-signal>Type "rating-done" when the content rating certificate is generated (green check) and the category is set to Games → Puzzle.</resume-signal>
</task>

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 4: Build signed AAB and upload to Internal Testing track</name>
  <what-to-do>
Build a fresh signed release AAB and upload it to Google Play Console.

Prerequisites:
  - `.env.local` must contain your real `VITE_RC_API_KEY` (set in Plan 15-01 Task 2).
  - `android/local.properties` must have RELEASE_KEYSTORE_PATH, RELEASE_KEYSTORE_PASSWORD,
    RELEASE_KEY_ALIAS, RELEASE_KEY_PASSWORD set (configured in Phase 9).
  - Android Studio must be open with the project loaded.

Build steps:
  1. Run in terminal:
     ```
     npm run build
     npx cap sync android
     ```
  2. Open Android Studio (if not already open):
     ```
     npx cap open android
     ```
  3. In Android Studio: **Build** → **Generate Signed Bundle / APK...**
     - Select **Android App Bundle** → click **Next**
     - Key store path: your release keystore file
     - Key store password / Key alias / Key password: from local.properties
     - Build variant: **release**
     - Click **Finish**
  4. Wait for the build to complete. The output file location:
     `android/app/build/outputs/bundle/release/app-release.aab`
     Android Studio will show a notification with a link when done.

Upload to Play Console:
  5. Open https://play.google.com/console → select app **Alchemica**.
  6. Left menu: **Testing** → **Internal testing** → click **Create new release**.
  7. Click **Upload** → select `android/app/build/outputs/bundle/release/app-release.aab`.
  8. In the "Release notes" field enter: `Initial internal test release`
  9. Click **Save** → **Review release**.
  10. Confirm: Play Console shows "No issues found" (or only warnings — not errors).
  11. Click **Start rollout to Internal testing** → **Rollout**.
  12. The Internal Testing track now shows the release as **Active**.
  </what-to-do>
  <resume-signal>Type "aab-uploaded" when the signed AAB is live on the Internal Testing track (Active status in Play Console).</resume-signal>
</task>

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 5: Verify Play Console completeness and submit for review</name>
  <what-to-do>
Do a final completeness pass in Play Console before submitting for review.

Completeness check:
  1. Open https://play.google.com/console → select app **Alchemica**.
  2. Left menu: **Publish** → **Production** (or check the Dashboard page).
     Play Console shows a checklist. Go through any remaining items.
  3. Common remaining items and where to fix them:
     - Privacy policy URL: **Store presence → Store settings** → enter a URL.
       Quick option: create a simple privacy policy at https://app-privacy-policy-generator.firebaseapp.com
       and host it on GitHub Pages or any public URL.
     - Data safety form: **Policy → App content → Data safety** → fill in form.
       For Alchemica: no data collected from users (no accounts, no analytics).
       Check "No" for data collection → submit.
     - Target audience: **Policy → App content → Target audience** → select "18 and over"
       (or adjust to match your content rating).
  4. Ensure all sections show a green check (✓) or are optional (grey).

Submit for review (option A — promote to production):
  5. Left menu: **Testing** → **Internal testing** → find your active release.
  6. Click **Promote release** → **Production**.
  7. Set rollout percentage: start with **20%** (or lower for caution).
  8. Click **Review release** → confirm no errors → **Start rollout to Production**.
  9. Google Play will begin review (typically 1–3 business days for new apps).

Alternative — stay in Internal Testing first (option B — safer):
  5. Skip promotion for now. Add yourself as an internal tester:
     Left menu → **Testing → Internal testing → Testers** → add your Google account.
  6. Accept the testing invitation link → install and test purchases.
  7. Promote to production only after confirming purchases work end-to-end.
  8. Type "review-submitted" either way (option A submitted OR option B opted for staged rollout).

Pre-launch report:
  9. After any AAB upload, Play Console runs automated pre-launch tests.
     Left menu: **Android vitals → Pre-launch report** — check for CRITICAL issues.
     Warnings are acceptable. Crash-rate issues are blockers — fix before production rollout.
  </what-to-do>
  <resume-signal>Type "review-submitted" when the store listing has no red errors AND the AAB is submitted for review (or active on Internal Testing for staged rollout).</resume-signal>
</task>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine → Play Console | AAB upload contains compiled app code + signing certificate |
| Android app → Google Play Billing | RC SDK mediates all purchase calls; no raw billing API calls in app code |
| Play Console → Google Play servers | Google-managed — outside trust boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-05 | Information Disclosure | Release keystore file | accept | local.properties is gitignored (Phase 9); keystore stays on developer machine only |
| T-15-06 | Tampering | AAB binary integrity | accept | Google Play verifies APK/AAB signing certificate on upload; Play Signing enforces integrity |
| T-15-07 | Information Disclosure | Privacy policy absence | mitigate | Task 5 step 3 includes creating and linking a privacy policy before production submission |
| T-15-08 | Repudiation | Purchase verification without receipt | accept | RC SDK handles server-side receipt validation; no custom server validation needed at this scale |
</threat_model>
