<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| initIAP() at app start → RC server | First network call on every native app launch |
| $purchasedNoAds store → HintButton render | Store value controls ad button visibility |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Spoofing | initIAP() RC_API_KEY = 'goog_REPLACE_ME' | mitigate | iap.ts has a prominent TODO comment. Build gate (Task 3) will succeed with placeholder key — the key only fails at runtime on device. Before Play Store submission, developer must replace RC_API_KEY in iap.ts with the real key from RevenueCat dashboard. |
| T-12-02 | Elevation of Privilege | purchasedNoAds guard bypass | accept | The !$purchasedNoAds guard only hides the ad button (a convenience, not a paywall). A rooted user who modifies the store gets... no ads. Not a meaningful security threat. |
| T-12-03 | Denial of Service | initIAP() + initAdMob() both in onMount | accept | Both calls are fire-and-forget (no await). Layout renders immediately — neither call blocks the app from loading. Both have try/catch internally. |
| T-12-04 | Information Disclosure | RC_API_KEY in built APK | accept | See T-12-03 in Plan 02: goog_ keys are designed to be embedded in APKs. RC server-side rules prevent unauthorized purchases. |
</threat_model>
