<objective>
Migrate the versioned save format from v2 to v3, folding hintBalance into the main
save object and adding the purchasedNoAds field.

Purpose: v2 stores hintBalance in a separate localStorage key ('alchemica_hint_balance').
v3 moves it into the unified versioned save (consistent, exportable, importable).
purchasedNoAds must persist across sessions so the ad button suppression and UI state
survive app restarts without waiting for the RevenueCat server response.

Output:
- game.ts: SAVE_VERSION=3, SaveData v3 interface, v2→v3 migration, updated saveToStorage
- storage.ts: EXPORT_VERSION=3, SaveFile v3 interface, updated exportSave/importSave

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage v2 save → v3 migration | Old data crosses schema version boundary |
| Imported save file (user-provided JSON) → stores | Untrusted JSON from user's filesystem |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | importSave — purchasedNoAds from file | accept | A user who edits their JSON save to set purchasedNoAds=true only suppresses ads for themselves. No server-side content is gated. RC re-validates on app start and overwrites the store value if the entitlement is not active. |
| T-12-02 | Denial of Service | loadSave() v2→v3 migration | mitigate | Migration is wrapped in the existing outer try/catch in loadSave(). Any exception returns null → fresh game state. No user data loss — v2 save still in localStorage untouched until SAVE_VERSION=3 write succeeds. |
| T-12-03 | Information Disclosure | alchemica_hint_balance key persists post-migration | accept | The stale key holds only a number (hint count). resetGame() already removes it. Harmless if it persists — will be overwritten to 0 on next migration. |
| T-12-04 | Tampering | hintBalance from imported save | accept | User can set hintBalance=999 in an exported save file. Acceptable: hints are a UX convenience, not a paid feature. Paid feature (purchasedNoAds) is RC-server-validated on start. |
</threat_model>
