# Phase 9: Capacitor Native Shell — Context

**Gathered:** 2026-05-02
**Status:** Ready for planning

<domain>
## Phase Boundary

Wrap the existing SvelteKit PWA as a native Android app via Capacitor. No new game features. Deliverables: a runnable Android app with correct identity, icons, splash screen, signed release AAB, and a haptics layer that works on both native and web.

**In scope:**
- Capacitor install + Android platform setup
- `capacitor.config.ts` with correct app ID and build dir
- Splash screen and status bar configuration
- Release keystore generation + Gradle signing config (gitignored)
- `@capacitor/haptics` with `navigator.vibrate` web fallback
- Signed release AAB buildable from local machine
- PWA web build continues to work identically (PLAT-03 gate)

**Out of scope:**
- New UI screens (main menu, profile, settings redesign) — separate phase
- iOS/App Store — v4
- AdMob, IAP — Phases 11–12
- CI/CD for Play Store deploy — future phase

</domain>

<decisions>
## Implementation Decisions

### App Identity
- **D-01:** App ID: `io.alchemica.app` — permanent, locked for Play Store registration
- **D-02:** Display name: `Alchemica` — matches existing PWA `short_name`
- **D-03:** Capacitor app name in `capacitor.config.ts`: `Alchemica`

### Plugin Scope
- **D-04:** Install in Phase 9: `@capacitor/core`, `@capacitor/cli`, `@capacitor/android`, `@capacitor/splash-screen`, `@capacitor/status-bar`, `@capacitor/haptics`
- **D-05:** Orientation locked to landscape at the native level — set `screenOrientation: "landscape"` in `capacitor.config.ts` (matches PWA manifest `orientation: "landscape"`)

### Signing & Release Build
- **D-06:** Generate a release keystore in Phase 9 — full PLAT-02 compliance (signed AAB) from the start
- **D-07:** Keystore stored locally; passwords in `android/local.properties` (gitignored). Never committed. Plan should document the `keytool` command and `build.gradle` signing block.

### Haptics
- **D-08:** Upgrade `src/lib/utils/touch.ts` to use `@capacitor/haptics` — replace `navigator.vibrate` calls with `Haptics.impact()` / `Haptics.notification()`
- **D-09:** Keep web fallback: check `Capacitor.isNativePlatform()` — use `@capacitor/haptics` on native, fall back to `navigator.vibrate` on web/PWA. PLAT-03 (web build unchanged) is preserved.

### Build Integration
- **D-10:** `capacitor.config.ts` must point `webDir` to `build` (SvelteKit adapter-static outputs to `build/`, not `dist/`)
- **D-11:** Add npm scripts for native workflow: `"cap:sync": "npm run build && npx cap sync"`, `"cap:android": "npm run cap:sync && npx cap open android"`, `"cap:build": "npm run build && npx cap sync && cd android && ./gradlew bundleRelease"`

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `touch.ts` haptic helpers: `hapticSuccess()`, `hapticFail()`, `haptic()` — wrapper layer makes the Capacitor upgrade a drop-in (change only the internals, callers unchanged)
- `static/icon-192.png`, `static/icon-512.png` — existing PWA icons; use as source for Android icon generation via `@capacitor/assets` or manual placement

### Established Patterns
- `adapter-static` with `fallback: 'index.html'` — SPA mode; Capacitor wraps this correctly; output dir is `build/`
- `vite-plugin-pwa` is in `vite.config.ts` — must not be removed or broken; web build and native build share the same Vite output
- `basicSsl` plugin in vite.config.ts — dev-only HTTPS; harmless for native builds (Capacitor doesn't use Vite dev server for the APK)

### Integration Points
- `capacitor.config.ts` (new) — entry point for all Capacitor config; sets appId, appName, webDir, plugins
- `android/` directory (generated by `npx cap add android`) — Gradle project, do not hand-edit except for signing config in `android/local.properties` and `android/app/build.gradle`
- `src/lib/utils/touch.ts` — haptics upgrade touches only this file; all callers (`MixingChamber.svelte`, etc.) remain unchanged

</code_context>
